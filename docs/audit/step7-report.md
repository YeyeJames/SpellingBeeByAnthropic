# 實測前檢查　步驟七：家長報告與行為紀錄

> 這一步**沒有改任何程式**，只加了一支測試：`scripts/report-math-test.mjs`（在 `test:all` 裡）。

## 1. 每一個數字都跟手算的答案對過
做法：放一批「答案已知」的資料進資料庫，每一筆都寫明它該被算進哪一格。資料分成三段時間：
- 3 天內：7 天、30 天都要算
- 20 天前：只有 30 天要算
- 60 天前：都不算

再跟報告的計算結果、以及報告頁上畫出來的文字逐項比對。

| 項目 | 結果 |
|---|---|
| 練習：練完幾組、答幾題、答對比例 | ✅ |
| 遊戲：幾場、贏幾場、戰役／複習關／組別各幾場 | ✅ |
| 戰役：打到第幾關、第一次就輸的比例、打最多次的關卡 | ✅ |
| 英打速度：每週一個點、同一週取中位數、跨週分開 | ✅ |
| 漏字原因：來不及／不會拼／沒動作、最常不會拼的字 | ✅ |
| 時間花在哪一頁 | ✅ |
| 三選一：次數、中位數、一秒內就選的比例、選了什麼 | ✅ |
| 小遊戲：次數、各玩幾次、每練完一組玩幾次 | ✅ |
| **7 天／30 天的範圍**：20 天前的只在 30 天出現，60 天前的都不出現 | ✅ |
| 兩個帳號的資料不會混在一起 | ✅ |
| 範圍亂填（0、9999）：退回 1～90 天之間 | ✅ |
| 報告頁畫出來的文字、下載分析檔的連結跟著範圍變 | ✅ |

**33 項全部正確。**

## 2. 兩週後資料有多大
用遊戲引擎打完整的一場，量錄影檔的大小：

| 一場 | 按鍵紀錄 | 存進資料庫 |
|---|---|---|
| 第 1 關（40 字） | 222 筆 | 5 KB |
| 中王（20 字） | 100 筆 | 2.5 KB |
| 第 3 章（30 字） | 155 筆 | 4 KB |
| **大魔王（100 字，最大的）** | 651 筆 | **14 KB** |

打錯很多的一場大約 20 KB。上傳的上限是 400 KB，本機暫存最多 5 份，都很寬。

**估算**：每個帳號每天打 8 場、練 100 題、點 150 下，大約 100 KB。
- 三個帳號兩週：**約 4 MB**。資料庫免費方案是 512 MB，不用擔心
- 下載分析檔：30 天大約 10 MB 以內。檔案太大傳不上來的話，報告頁選「最近 7 天」再下載就好
- 90 天後資料庫會自己刪（TTL，步驟三在真的 MongoDB 上確認過有建）

## 3. 行為紀錄會不會拖慢畫面
量的是最壞的情況：
- 離線很久，暫存塞到上限 500 筆（64 KB）
- 再把電腦模擬成**慢 6 倍**

| 電腦 | 記一筆事件（中位數） | 最慢 |
|---|---|---|
| 一般速度 | 1.1 ms | 19 ms（一次） |
| 慢 6 倍 | 7.1 ms | 14 ms |

畫面一格是 16 ms，孩子感覺不到。平常每 15 秒就會送出、暫存很少，比這個更快。
戰鬥中不是每一個按鍵都記：只記開打、三選一，按鍵在錄影檔裡、打完才送一次。**沒有效能問題。**

## 4. Q5：報告的「一週」用國際時間切
台灣時間**星期一 0:00～7:59** 玩的那幾場，會被算進前一週。孩子都是下午、晚上玩，實際上不會遇到。**建議不改。**

## 5. 其他確認過的
- 家長看報告的時間不會被記成孩子的（telemetry-test）
- 下載分析檔不含登入資訊、不含舊密碼欄位、不含內部 id（telemetry-test）
- 刪帳號時行為紀錄一起刪（telemetry-test、步驟三在真的 MongoDB 上）
- 你的測試帳號會出現在報告裡，跟孩子的分開一份；我分析時會單獨拿出來

## 結論
報告算得對、資料量很小、不會拖慢畫面。**這一步沒有要修的。**
