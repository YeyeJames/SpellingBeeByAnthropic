# 實測前檢查　步驟八：兩週模擬、分析檔健檢、測試本身的可靠度、最終回歸

> 這一步**沒有改任何遊戲程式**。改的只有測試與檢查工具。

## 1. 模擬兩個孩子各用 14 天，最後對帳
`node scripts/audit/step8-two-weeks.mjs`（真的 MongoDB＋真的伺服器，約 2 分鐘；不在 `test:all` 裡）

- **網路重試**：一成的請求原封不動再送一次，模擬背景佇列在重試

## 2. 分析檔健檢
`npm run export-check -- 下載的分析檔.json`

實測期間家長每週下載一次分析檔給我，我跑這一支。它找的是「沒有報錯、但悄悄算錯」的：
- 負的金幣、蜂蜜、經驗
- **每一題用現在的規則重判一次**：也順便查得出 4-A 上線前，有沒有全形字被判錯、有幾題
- 別本課本的字（step2 的 S1）
- 同一筆記了兩次
- 戰役打贏了卻沒記到過關
- 錄影檔分析失敗、停在「還在打」、有幾場沒有錄影檔
- 沒買的小遊戲有玩
- 停在同一頁超過 3 小時

**驗證**：`scripts/export-check-test.mjs`（在 `test:all` 裡）。
- 乾淨的分析檔：全部 ✅
- 故意埋 14 種錯：每一種都抓到
- 兩週模擬匯出的分析檔：沒有要追的

## 3. 測試本身的可靠度

### 飄分測試（步驟五、六一直沒過的那一支）
- **原因**：它一個延遲都沒有地連按（每秒幾百個鍵），量到的是「這台機器畫得多快」，所以同一份程式在不同機器上有時過、有時不過
- **改法**：照 `effects.js` 設計的最快手速（每 120 毫秒一個字母）連打，一邊打一邊量
- **結果**：最多同時 7 個（上限 12），連跑 3 次通過。遊戲本身沒改

### 假造的伺服器回應（step1 的 G2／Q7；step6 的主題 bug 就是被它藏住的）
- `scripts/audit/mock-recorder.cjs`：跑測試時，把所有假造的回應記下來
- `scripts/audit/mock-drift.mjs`：對每一個被假造的端點，打一次真的伺服器，比對欄位與狀態碼

**結果**：9 支測試、15 個端點、84 個假回應逐一比過，沒有危險的差異。
- 「假的是錯誤、真的是成功」的那幾個是測試**故意**做的（名字打錯、沒登入、資料庫掛了）
- 唯一真的不一樣：兩支測試假造的使用者有 `username`，真的伺服器是 `nickname`。沒有任何程式讀 `username`，不影響功能，但已經改成跟真的一樣

## 6. 實測期間怎麼做
1. **每週一次**：報告頁按「下載分析檔」，把檔案給我；我跑 `npm run export-check -- 檔案.json`，有 ⚠️ 才追
2. **發現怪怪的**：記下 哪一頁、做了什麼、看到什麼、大概幾點，能截圖最好；如果是打怪時，按畫面上的「剛剛怪怪的」，電腦會下載一個錄影檔，把它一起給我
3. **修正上線的時間**：平日在早上（孩子下午、晚上才玩）；週末、假日當天要推就直接推。每一筆修正都先跟家長說，確認後才推
4. **使用習慣**：一台電腦只開一個分頁；換人玩用右上角 ▾ →「換人玩」
5. 爸爸的測試帳號：分析平衡（關卡難度、贏的機率）時**排除**，只看兩個孩子
