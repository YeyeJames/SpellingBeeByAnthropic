# 拼字蜂：蜂巢保衛戰 — 遊戲設計計畫書

> 把聽寫練習從「問答題 + 金幣計數器」改造成一款**以打字為武器的塔防 Roguelite**。
> 核心迴圈不變：聽發音 → 打出來 → 比速度與正確率。變的是這個動作在遊戲裡的意義。

---

## 目標平台（設計前提）

**主要：桌機瀏覽器（實體鍵盤）。次要：iPad 橫向。手機不在設計目標內。**

這個前提決定了下面所有版面與數值，不是註腳：

| 影響 | 因為有實體鍵盤與大螢幕 |
|---|---|
| 構圖 | 16:9 全螢幕橫向，畫面高度完整可用，不必為虛擬鍵盤讓位 |
| 操作 | **全鍵盤，不需要滑鼠**。重聽／慢速／例句改成按鍵，手不離鍵盤 |
| 手感 | 連續快速打字才能打出音階節奏感——這在觸控螢幕上做不出來 |
| 演出 | 粒子、視差、後製特效可以開到桌機 GPU 的水準 |

iPad 橫向沿用同一套版面，只是把三個聽力按鍵放回螢幕上（外接鍵盤時同桌機）。
若 iPad 用螢幕鍵盤，可用高度約剩六成——**戰鬥場景維持又寬又扁的構圖就能相容**，不需要第二套版面。

---

## 內容規模（設計前提之二）

單字庫不只是那 100 個競賽字，後續還會加入 Week 1~18，每組約 39~40 字。

| 項目 | 數量 |
|---|---|
| 競賽單字 | 100（Part 1~4，各 25） |
| Week 1~18 | 約 720（每組 39~40） |
| **總計** | **約 820 字、22 組** |
| 每個字的精熟標準 | 近乎完美表現 5~6 次 |
| **總單字輸入次數** | **約 4,500 次** |
| 一場 Run（一組 40 字） | 約 10~13 分鐘 |
| **總遊戲場次** | **約 120 場、合計約 24 小時** |

**24 小時是這份設計真正要通過的考驗。** 一個會玩 Minecraft 的小孩花 24 小時不算什麼——
但那是因為 Minecraft 24 小時內一直有新東西。我必須誠實說：**目前寫的 15 個能力撐不到 120 場**，
大概第 15~25 場就會開始重複。Slay the Spire 能讓人玩幾百場是因為它有 350 張卡；我們不需要 350，但 15 個絕對不夠。

### 每組的 5~6 次不是重複五六遍，是一道階梯

| 第幾次 | 關卡型態 | 內容 |
|---|---|---|
| 1 | **認識關** | 先顯示單字再唸，低風險、不會死，只求走過一遍 |
| 2~3 | **標準關** | 正常戰鬥，開始計分 |
| 4 | **精英關** | 沒有例句可聽、敵人速度 +25% |
| 5~6 | **認證關** | 每個字只唸一次，正確率 ≥ 95% 才算通過 |

通過認證＝該組標記「已征服」，全組單字升到圖鑑最高階（等同 Leitner 第 5 箱）。
認證關強制走全戰鬥路線（不能靠繞商店少練字），其餘場次路線自由。

### 撐住 120 場需要的內容量

| 項目 | 目前計畫 | 實際需要 |
|---|---|---|
| 能力 | 15 | **約 45**，隨精熟組數逐步解鎖（每精熟 2 組開出 2 個新能力） |
| 敵人種類 | 未定 | 12~15 種，按週次排程登場 |
| 場景 biome | 1 | 6 種，每 3 組換一次 |
| 每組修飾 | 無 | **18 種週修飾**：濃霧（不能聽例句）、蜂群（敵人成對出現）、逆風（擊退減半）… |

關鍵是**不要一開始就全部給**。能力全開在第 1 場，新鮮感第 10 場就用完；
分 18 週慢慢開，每一組新單字都伴隨一個沒看過的東西。

> **長期進度的主軸是單字圖鑑，不是蜂蜜。** 820 個字、每個字 0~5 級，這條進度條剛好撐滿一整個學年，
> 而且它直接等於「他真的學會了多少」——遊戲進度與學習進度是同一件事，不是兩套系統。

### 這對架構的要求（Phase 1 就要定）

所有內容都必須是**資料檔**，不是寫死的場景：加一週單字＝貼一份資料；加一個能力＝加一筆設定 + 一個效果函式；
加一個週修飾＝加一筆設定。**如果第一版把關卡寫死，第 10 週就會卡死。**
現有的 `word-bank.js` 也要從 `part: 1~4` 改成通用的「組」（`group`），讓 Week 1~18 直接貼進去就能用。

## 0. 為什麼要改

現有版本的問題不在畫面，在三件事：

| 問題 | 現況 | 改造後 |
|---|---|---|
| 打字不是動作，只是表單 | 輸入 → 按送出 → 播放獎勵動畫。獎勵發生在打字**之後**，與打字本身無關 | 每按對一個字母就是一次攻擊，敵人當場被擊退 |
| 不會輸 | 只有獎勵沒有風險 | 有血量、會失敗、一場冒險會結束 |
| 每次都一樣 | 每場流程完全相同 → 「又來了」 | 路線、能力三選一、角色，每場都不同 |

**買帽子只改變外觀，買「連對 3 個字進入子彈時間」才會改變你怎麼玩。** 這是整份設計的中心思想。

## 1. 三層結構

```
Layer 3  一次冒險 Run        ← 路線選擇、能力三選一、王關（8~13 分鐘）
  └ Layer 2  一場戰鬥 Battle  ← 敵人波次、血量、連擊（1~2 分鐘）
      └ Layer 1  一次輸入      ← 逐字母即時回饋（3~8 秒）
```

Layer 1 決定「爽不爽」，Layer 2 決定「緊不緊張」，Layer 3 決定「會不會膩」。
三層都要做，但**Layer 1 是成敗關鍵**。

---

## 2. Layer 1：一次輸入（最重要）

這一層做對了，整個遊戲就成立；做錯了，後面再華麗都沒用。

### 規格

畫面上不顯示已打的字母文字，改成一條**能量槽**與敵人身上的裂痕。

**每按對一個字母：**
- 蜂針飛出擊中敵人（約 0.1 秒），敵人閃白並後退一小段
- 一片字母碎片飛向蜂巢
- **打擊音音高遞增**：第 1 個字母 C、第 2 個 D、第 3 個 E⋯ 打完一個字剛好是一段上行音階

> 這個音階設計是整個手感的核心。打字遊戲之所以讓人上癮，很大一部分來自「每個按鍵都有回應、而且連起來變成旋律」。

**打完最後一個字母：**
- 敵人爆開成蜂蜜噴濺，畫面輕微頓挫（hit stop，約 80ms）
- 下一隻敵人立刻上前，發音自動播放

**按錯字母：**
- 畫面紅閃 + 震動 + 低沉錯誤音
- 敵人前進一步
- **不清空已打的內容**，那個錯誤字母單純不被接受，繼續打正確的即可（避免小孩挫折到放棄）

### 不能省的細節

- **沒有送出鈕**：最後一個字母打完當下就結算
- **壓力是看得見的**：是敵人在逼近，不是一條抽象的進度條
- **重聽有代價**：見下表。現在「再聽一次」免費，所以完全沒有張力

| 動作 | 按鍵 | 代價（敵人前進相當於幾秒的距離） |
|---|---|---|
| 再聽一次 | `↑` | 1.5 秒 |
| 慢速重聽 | `↓` | 2.5 秒 |
| 聽例句 | `→` | 2.0 秒 |

### 鍵盤配置（桌機）

方向鍵不與任何字母衝突，而且就在右手邊、緊鄰 Enter，小孩不用學就會按。

| 鍵 | 功能 |
|---|---|
| A~Z | 拼字（就是攻擊） |
| `↑` `↓` `→` | 再聽／慢速／例句 |
| `Backspace` | 刪掉最後一個字母（不扣血、不讓敵人前進） |
| `Esc` | 暫停 |

**全程不需要滑鼠**，包括地圖選路線與三選一能力（`←` `→` 選、`Enter` 確定）。
輸入焦點永遠鎖在遊戲上，玩家不會「打了半天發現沒打進去」。

## 3. Layer 2：一場戰鬥

### 場景

橫向單線道。左邊是蜂巢（你的基地），右邊是入侵口，敵人由右向左推進。

畫面上**同時有 3~5 隻敵人排隊**（製造視覺壓力），但只有最前面那隻是當前目標——因為聽寫一次只能聽一個字。

桌機 16:9 全螢幕，畫面由下往上分三段：**戰場（約 65%）／能量槽與血量 HUD（約 15%）／敵人隊列與 Combo（約 20%）**，
整場戰鬥不捲動、不切換視角，眼睛只需要在戰場中央來回。

> 構圖仍維持**又寬又扁的橫向長條**——不是為了手機，而是因為敵人是橫向逼近的，
> 而且這樣同一套版面在 iPad 螢幕鍵盤彈出時（可用高度剩約六成）不用改就能用。

### 數值

| 項目 | 數值 |
|---|---|
| 起始血量 | 3 顆蜂蜜罐 |
| 敵人橫越畫面時間 | **基礎時間（聽）＋ 每字母時間 × 字母數**（見下方難度） |
| 打錯一個字母 | 敵人前進 1 秒的距離 |
| 敵人抵達蜂巢 | 扣 1 血，該單字重新排進本場隊列 |
| 血量歸零 | 本次冒險結束 |

時間**跟著單字長度走**，不是固定值——否則短字太鬆、長字必死，小孩會學到「看到長字就放棄」。

**難度（可設定，也會自動微調）**

| 模式 | 公式 | `account`（7 字母） | 模擬失敗率 | 適用 |
|---|---|---|---|---|
| 輕鬆 | 3.6 + 1.05×字母 | 11.0 秒 | 10.5% | 剛開始、打字還不熟 |
| 標準 | 2.4 + 0.62×字母 | 6.7 秒 | 20.0% | 預設 |
| 挑戰 | 1.3 + 0.38×字母 | 4.0 秒 | 23.5% | 熟練之後 |

> **這組數字是跑出來的，不是訂出來的。** 平衡模擬器掃過 108 組候選值、
> 每組跑 9 種「手速 × 難度」組合各 120 場，挑出讓每個檢查點都落在預期區間的那一組。
> 原本三個難度共用 3 秒的基礎時間，結果難度之間拉不開——快手速在三個難度都零失誤，
> 因為光那 3 秒就夠他聽完並開始打。**基礎時間也要跟著難度縮短**，難度才真的分得開。
> 上表的失敗率是手速與難度相稱時的數字；差一階會吃力，差兩階幾乎必輸，
> 這正是難度校準存在的理由。

**第一次開始遊戲時先校準**：用 3 個已經很熟的字量他的實際按鍵間隔，直接建議起始難度，不要讓他第一場就被打爛。

自動微調：連續 3 場正確率 > 90% 就建議升一階；連續 2 場血量歸零就建議降一階（詢問而非強制，讓小孩自己選）。

### 連擊 Combo

連續打對且不失誤時累積，打錯歸零。

| Combo | 效果 |
|---|---|
| 5 | **蜂群衝刺**：3 秒內敵人減速 50% |
| 10 | **蜜糖時間**：下一個單字的時間 ×2 |
| 15 | **狂蜂狀態**：5 秒內擊退 ×3、蜂蜜 ×2 |

> Combo 的獎勵一律是「更好打」，**不是「不用打」**。原本 Combo 10 設計成自動擊殺，那會直接少掉一次聽與一次輸入——
> 爽度可以用時間加倍換到，學習次數不能折抵。這條原則對所有能力同樣適用（見〈遊戲平衡〉）。

## 4. Layer 3：一次冒險 Run

### 結構

一個 Run = **一組單字**（競賽 Part 為 25 字，Week 組為 39~40 字），約 8~13 分鐘。

地圖分 5 層，每層有 2~3 個節點可選，玩家**自己選路線**：

```
        ┌─ 戰鬥 ─┐     ┌─ 精英 ─┐     ┌─ 戰鬥 ─┐
  起點 ─┤        ├─選擇─┤        ├─選擇─┤        ├─ 王關
        └─ 商店 ─┘     └─ 寶箱 ─┘     └─ 商店 ─┘
```

節點的單字數 =「該組字數 ÷ 5」，所以同一套地圖同時吃得下 25 字與 40 字的組：

| 節點 | 單字數（25 字組 / 40 字組） | 內容 |
|---|---|---|
| 一般戰鬥 | 5 / 8 | 標準敵人 |
| 精英戰鬥 | 6 / 10 | 敵人速度 +25%，但獎勵是**稀有能力** |
| 商店 | 0 | 用本場蜂蜜買能力或補血 |
| 寶箱 | 0 | 隨機獲得一個能力，或補 1 血 |
| 王關 | 5 / 8 | 見下方 |

**路線是真正的取捨**：全部走戰鬥＝整組練滿、蜂蜜最多；多走商店寶箱＝能力更強但練得少（沒練到的字下一場會回來）。
唯一的例外是**認證關（第 5~6 次）強制全戰鬥**，不能靠繞路少練字。

每通過一個節點，**三選一**拿一個能力。

### 王關

- 出題優先選**這一組裡最常打錯的字**（直接接現有的 Leitner 資料）
- 每個字**只唸一次**（除非有「回音水晶」能力）
- 王有護盾：每個單字要**連續打對兩次**才能擊破
- 打倒後：該組標記為「已征服」，解鎖這一組的獎盃

## 5. 能力（三選一）

讓每場不同的關鍵。玩家每場約拿到 4~5 個，抽 3 個選 1。

下面是**第一批 15 個**，用來把各個類型的設計方向定下來；完整目標是約 45 個，隨精熟組數分週解鎖（見〈內容規模〉）。

### 攻擊型
| 名稱 | 效果 |
|---|---|
| 蜂針強化 | 每個正確字母的擊退 +30% |
| 首字重擊 | 每個單字第一個字母打對，敵人直接後退一半 |
| 長字獵手 | 7 個字母以上的單字，蜂蜜獎勵加倍 |

### 防禦型
| 名稱 | 效果 |
|---|---|
| 蜂蠟護盾 | 每場戰鬥開始時獲得 1 點臨時護盾 |
| 二次機會 | 每場戰鬥第一次漏字不扣血 |
| 蜂巢加固 | 血量上限 +2 |

### 聽力型
| 名稱 | 效果 |
|---|---|
| 回音水晶 | 重聽不再讓敵人前進 |
| 慢速大師 | 慢速重聽的代價減半 |
| 例句直覺 | 每個字可以免費聽一次例句 |

### 連擊型
| 名稱 | 效果 |
|---|---|
| 蜜糖節奏 | Combo 門檻從 5 降到 3 |
| 連鎖反應 | Combo 每 +1，蜂蜜獲得 +5% |

### 風險型（高風險高報酬）
| 名稱 | 效果 |
|---|---|
| 玻璃蜂針 | 傷害 ×2，但血量上限變成 1 |
| 盲打之證 | 關閉螢幕上的能量槽提示，蜂蜜 ×2 |
| 一發入魂 | 每個字只能聽一次，但擊殺獎勵 ×3 |

> 風險型能力是讓小孩覺得自己「很會玩」的來源，也是每場差異最大的部分。一定要有。

## 6. 跨場進度（Meta）

### 蜂蜜
Run 結束時（不論勝敗）保留一部分蜂蜜，用來永久解鎖。**失敗也有收穫**，這點很重要。

### 角色（改變規則，不只是外觀）

| 角色 | 特性 |
|---|---|
| 工蜂（預設） | 平衡 |
| 偵察蜂 | 敵人速度 −20%，但血量只有 2 |
| 兵蜂 | 血量 5，但重聽代價加倍 |
| 蜂后 | 每場多一次三選一，但敵人多 1 隻 |

### 單字圖鑑
每個單字打對 N 次會被「馴服」，收進圖鑑，共 0~5 級（等同 Leitner 五箱）。**820 個字全馴服 = 最終成就。**
這是給 Minecraft／寶可夢世代的收集要素，也是撐滿一整個學年的長期進度主軸。

### 現有商店怎麼辦
造型／主題／小遊戲併入 meta 解鎖（用蜂蜜買），不再是獨立分頁。

---

## 7. 學習效果不能被犧牲

遊戲化不能變成「玩得開心但沒學到」。以下是硬性要求：

- 本場漏掉或打錯的字，**在同一場 Run 內重新排隊**（立即複習）
- Run 結束後這些字進入既有的 Leitner 間隔複習佇列
- 王關優先出現該 Part 最弱的字
- 統計完整保留：正確率、平均反應時間、每個字的熟練度、最常錯的字母位置
- 家長可在「我的檔案」看到完整數據（這部分維持現狀）

## 8. 遊戲平衡

平衡不是「感覺一下」，是可以量測的。先把目標寫成數字，才有辦法檢查有沒有達成。

### 平衡目標（可量測）

| 關卡 | 目標失敗率 | 理由 |
|---|---|---|
| 認識關 | < 5% | 第一次接觸新單字不該死，死了會排斥新的一週 |
| 標準關 | 15~25% | 有張力但不挫折 |
| 精英關 | 30~40% | 要讓人猶豫該不該走 |
| 認證關 | 首次通過率 45~55% | 認證要有份量，但第二次應該就過得了 |

**整組從第 1 次到通過認證，平均應落在 5~6 場。** 這正是你設定的標準，所以它同時是平衡目標與驗收條件——
如果模擬出來要 9 場，代表太難；如果 3 場就過，代表太鬆，兩種都要調。

### 所有數值集中在一個檔案

`balance.js` 一個檔管全部：敵人時間公式（base / perLetter × 三段難度）、打錯懲罰、重聽代價、血量、
Combo 門檻、蜂蜜公式、能力強度區間、各關卡修正係數。**任何數值都不准散落在場景程式碼裡**，
否則調一次平衡要翻十個檔案，就不會有人去調。

### 怎麼驗證：離線平衡模擬器

這是這一節的重點，也是我實際做得到的事：**寫一個模擬器，用玩家模型跑一萬場。**

玩家模型的參數：
- 每字母打字時間（平均值 + 標準差，從他真實的遊玩資料校準）
- 單字熟練度 → 打錯機率（用既有的 Leitner 等級推）
- 重聽機率（熟練度愈低愈常重聽）

模擬器輸出：
- 各關卡失敗率 vs. 上表目標
- 每組平均通關場次（目標 5~6）
- **每個能力的勝率排行**——哪個過強、哪個沒人選
- 蜂蜜通膨曲線（會不會中期就買爆）

**價值在於：調完數值立刻重跑，不必等小孩玩 100 場才發現不平衡。**
這是 Phase 2 的交付物之一，不是額外功能。之後每加一批能力都要重跑一次。

### 能力平衡原則

- **不做純數值的無聊能力**（「傷害 +10%」），也不做破壞性能力（「直接跳過這個字」）
- 任一能力的勝率偏離基準 ±15% 就要調整
- 風險型能力必須**真的可能害你輸**，否則它不是風險，是免費獎勵
- **絕對禁止任何能力減少「必須聽 + 必須打」的次數**——這是學習底線，不能用遊戲性交換
  （所以「Combo 10 自動擊殺下一個字」要改成「下一個字時間 ×2」，效果一樣爽，但字還是要打）

### 難度微調到單字層級

除了整場難度，**單字層級也要微調**：某個字連續錯 3 次 → 下次出現時自動多給 30% 時間，
但那一次不計入精熟次數。讓他過得去，但不會假裝學會了。

## 9. 操作流暢（手感工程）

這一節是「爽不爽」的技術面。**這些沒做，前面所有設計都感覺不出來。**

### 延遲預算

| 環節 | 預算 |
|---|---|
| keydown → 音效發聲 | < 20ms |
| keydown → 畫面出現回饋 | ≤ 1 影格（16ms） |
| 端到端 | **< 35ms** |

做法：音效用預先建好的節點，不在 keydown 當下才臨時建立；
畫面回饋採「立即改狀態 + 下一影格補動畫」，不等 tween 開始才有反應。

### 60fps 不掉格

- **物件池**：蜂針、粒子、字母碎片全部 pool 重用，**戰鬥中不新建任何物件**（避免 GC 造成的偶發卡頓，那是最難查也最毀手感的問題）
- 進戰鬥前載完所有素材，**戰鬥中不載任何東西**
- 粒子總數設上限，Combo 15 爆發時也要 cap
- 使用 texture atlas 減少 draw call

### 輸入處理的細節（沒做就會「怪怪的」）

- 用 `keydown`，並在 `e.repeat` 為真時忽略——**按著不放不該連發**
- **輸入緩衝**：他打得比動畫快時，按鍵不能被吃掉；先記錄，動畫追上再演
- 擊殺轉場的那 100ms 內**仍然接受下一個字的輸入**，不要因為轉場吃掉他的手速
- 視窗失焦自動暫停（切去看別的東西回來不會已經死了）
- 全螢幕下攔截會干擾的瀏覽器快捷鍵
- 輸入法偵測（見風險表）

### 轉場不能卡

| 轉場 | 上限 |
|---|---|
| 單字之間 | < 300ms |
| 節點之間 | < 800ms |
| 場景之間 | < 1s |

全部用 tween 銜接，**不出現任何載入畫面**。

## 10. 美術

### 風格定調

深色背景、高對比、**剪影 + 亮色描邊（rim light）**。保留蜜蜂主題與現有吉祥物，
但加上戰鬥姿態與受擊動畫。敵人要有「對手感」而不是可愛：入侵蜂巢的甲蟲、黃蜂、蜘蛛，全部原創設計。
16:9 全螢幕橫向場景、三層視差捲動、遊戲畫面沒有導覽列。素材按 1920×1080 設計，iPad 等比縮放。

### 技術路線：向量 SVG 為主（這是個需要你知道的取捨）

我必須先說清楚產圖的現實：**我在這裡沒辦法繪製點陣圖，而免費素材站在這個環境連不上。**
可行而且品質穩定的作法是：

- **角色／敵人／道具**：我手寫 SVG——可無限縮放、可換色、檔案小、風格天然一致
- **背景**：SVG 圖層 + 程式化視差
- **特效**：全部程式化粒子，不需要任何圖檔
- **預留換圖插槽**：每個素材有固定路徑與尺寸，你之後若想放插畫風的圖，直接覆蓋同名檔案即可，程式不用改

誠實講：這條路做得出**乾淨、統一、專業的向量風格**（想像《Geometry Dash》《Alto's Odyssey》那種方向），
但做不出手繪插畫的厚度。如果你要插畫風，就需要你這邊提供圖檔（在別的地方產生都可以），我把插槽先留好。
**這個決定不影響進度**——先用 SVG 做到好，之後要換隨時能換。

### 素材清單（「做滿」的實際份量）

| 類別 | 數量 |
|---|---|
| 主角蜜蜂 | 4 角色 × 6 動作（待機／攻擊／受擊／衝刺／勝利／失敗） |
| 一般敵人 | 12~15 種 × 4 動作（前進／受擊／死亡／特殊） |
| Boss | 6 種（每 biome 一隻） |
| 場景 | 6 biome × 3 視差層 = 18 張背景 |
| UI | HUD、地圖節點圖示、**能力卡 45 張**、圖鑑卡框、結算畫面 |
| 特效 | 程式化：蜂針、字母碎片、蜂蜜噴濺、擊殺爆炸、combo 光環、受擊白閃、畫面震動 |

### 動畫原則

- 每個動作 6~8 幀，用向量 tween 而非逐幀圖（省素材、可即時調速）
- **Squash & stretch、anticipation、follow-through** 這三個基本功一定要做，這是「有沒有生命感」的分水嶺
- 擊殺：80ms hit stop + 輕微鏡頭震動（0.1s、4px）——**震動要克制**，過頭會讓人頭暈
- 不做任何會遮住輸入區或敵人隊列的動畫

## 11. 音效與音樂

**聲音在這個遊戲裡是回饋，不是背景。** 打字遊戲的爽感有一半來自聽覺。

### 音效清單（約 30 個，全部 Web Audio 合成）

| 事件 | 聲音 |
|---|---|
| 正確字母 | **上行音階** C-D-E-F-G-A-B-C'，依 Combo 轉調 |
| 錯誤字母 | 低沉短促 buzz |
| 擊殺敵人 | 破裂 + 蜂蜜噴濺 |
| 漏字扣血 | 低頻心跳 |
| 重聽 | 輕微 whoosh（用聲音提醒「這有代價」） |
| 三選一出現／選中 | 展開音／上揚 chime |
| Combo 5／10／15 | 三階疊加音，一階比一階厚 |
| 王關開始 | 低音鼓 + 蜂群嗡嗡 |
| 通過認證 | 完整的勝利短曲 |

全部合成的好處：**零音檔、零載入時間、可即時變調**，而且不會有版權問題。

### 背景音樂：分層自適應，不是一首 loop

四層（鼓／貝斯／和聲／旋律）依戰況疊加：

| 狀態 | 音樂 |
|---|---|
| 平常 | 鼓 + 貝斯 |
| Combo ≥ 5 | 加入和聲層 |
| Combo ≥ 10 | 加入旋律層 |
| 血量剩 1 | 轉小調 + 速度 +5% |
| 王關 | 另一組主題 |

每個 biome 一組和弦進行（共 6 組），所以 18 週不會一直聽同一個調。
**音樂直接反映戰況**——他會在音樂變厚的時候知道自己正在連擊，這比看數字強。

### 字母音階跟學習是連在一起的

打完 7 個字母是完整的上行七度，8 個字母正好回到八度。
**小孩會用耳朵記住一個單字有多長。** 這是遊戲性與學習性真正接在一起的地方，不是裝飾。

### 靜音也要能玩

家裡不一定隨時能開聲音。**所有聲音回饋都必須有對應的視覺回饋**，不能有任何資訊只存在於聲音裡。
另外提供音效校準（耳機與喇叭的延遲不同）、BGM／SFX 分開調整、一鍵靜音——這些現有系統已經有了，沿用。

## 12. 實作階段

| 階段 | 系統 | 同步的美術／音效 | 驗證點 |
|---|---|---|---|
| **1. 核心手感** | 逐字母回饋、全鍵盤操作、單一敵人逼近與擊退、難度校準、延遲預算達標 | 蜜蜂 + 1 種敵人的完整動作、字母音階、擊殺音、hit stop、蜂針與碎片粒子 | **給兒子在電腦上玩 5 分鐘** |
| 2. 一場戰鬥 | 多敵人排隊、血量、漏字、Combo、難度三階、**平衡模擬器** | 3 種敵人、第一個 biome 三層背景、分層 BGM 前兩層、Combo 三階音 | 一場戰鬥好不好玩 + 模擬器失敗率落在目標區間 |
| 3. Run 結構 | 地圖、節點、三選一、商店、王關、認證關 | 地圖節點圖示、能力卡框、王關主題音樂、勝利短曲 | 玩第二次還想玩嗎 |
| 4. Meta | 蜂蜜、角色、**單字圖鑑（長期主軸）**、併入現有商店 | 4 個角色的完整動作、圖鑑卡框、結算畫面 | 會想回來嗎 |
| 5. 內容量產 | 能力擴到約 45、12~15 種敵人、18 種週修飾，全部資料化並分週解鎖 | 其餘敵人與 Boss、6 個 biome、45 張能力卡、6 組和弦進行 | **第 30 場還有新東西嗎** |
| 6. 打磨與收尾 | 效能剖析、平衡重跑、無障礙檢查 | 轉場、鏡頭、粒子微調 | 60fps 不掉格、靜音也能玩 |

**美術與音效不是最後那一層。** 表格特意加了中間那一欄：Phase 1 如果沒有音階與擊退特效，
「核心手感」根本測不出來——你兒子那五分鐘要判斷的正是聲光回饋對不對。所以每個階段都帶自己的美術與音效一起交付。

Phase 5 的份量**可能比 1~4 加起來還大**。Phase 1~4 做的是「一場好不好玩」，Phase 5 做的才是「120 場撐不撐得住」——
它可以邊玩邊補（每週跟著新單字放新內容），但不能假裝不存在。

### ⚠️ 最重要的一句話

**Phase 1 做完就停下來，讓兒子玩五分鐘。**

如果他眼睛沒有亮起來，就不要往下做。核心手感對不對，五分鐘就看得出來，不需要等到整套做完。這是整個計畫最便宜的止損點——我們已經在這個專案上花了很多力氣做「完整但不好玩」的東西，不要再重複一次。

## 13. 技術決定

**不換平台，繼續用 Phaser。** 理由：

- 手感問題來自設計，不是引擎。Phaser 做 2D 動作遊戲綽綽有餘
- 這是唯一我能**自己跑起來、截圖、量測、驗證**的選項（這幾天抓到的 bug 幾乎都靠這個能力）
- 你零設定成本，打開瀏覽器就能玩，不用裝東西
- **桌機是瀏覽器最強的地方**：鍵盤事件精準、GPU 充足、Fullscreen API 可用。改以桌機為主之後，用網頁做這件事比之前更划算，不是妥協

桌機相關的實作要點：進入戰鬥時呼叫 Fullscreen API、鍵盤事件直接綁在 window 上（不經 `<input>`，避免輸入法與焦點問題）、
按鍵到畫面回饋的延遲要壓在一個影格內（16ms）——這是「打起來爽不爽」的實際來源。

**內容一律資料化**（因為要撐 820 字、120 場）：單字組、能力、敵人、biome、週修飾各自是一份資料檔，
程式只負責讀資料與執行效果函式。加一週單字或一個能力不應該需要改場景程式碼。

### 沿用現有系統
Leitner 複習（正好對應圖鑑 0~5 級）、暱稱+PIN 登入、進度統計、真人錄音 + TTS、本地優先同步、離線佇列。

### 需要改寫
- 練習頁 → 全螢幕遊戲場景
- 商店 → 併入 meta 解鎖
- **`word-bank.js` 的 `part: 1~4` → 通用的 `group`**（`{ groupId, kind: 'competition'|'week', label }`），
  讓 Week 1~18 直接貼資料就能用。這件事愈早做愈便宜
- Phaser 場景架構：從「一隻會跳的蜜蜂」變成真正的多場景遊戲（戰鬥場景、地圖場景、結算場景）

## 14. 已知風險

| 風險 | 說明 | 對策 |
|---|---|---|
| **中文輸入法** | 電腦停在注音模式時，按字母會跳出選字視窗，遊戲完全不能玩 | 偵測到輸入異常就跳全螢幕提示「請切回英文輸入法」，並在開始前先要求按一個字母確認 |
| 小四生打字速度 | 還在看鍵盤找字母，可能跟不上 | 時間跟著字母數走 + 開場校準 + 三段難度自動微調 |
| iPad 螢幕鍵盤 | 可用高度剩約六成 | 版面本來就是寬扁構圖，等比縮放即可；三個聽力鍵在 iPad 上顯示為螢幕按鈕 |
| 挫折感 | 連續失敗會放棄 | 二次機會、失敗也有蜂蜜、難度自動建議下調 |
| 打字練習變成反射練習 | 為求快而不思考拼字 | 王關只唸一次、長字加倍獎勵，鼓勵確實聽清楚 |
| **內容在第 20 場就用完** | 要撐 120 場、24 小時，15 個能力遠遠不夠 | 能力擴到約 45 個並分週解鎖、18 種週修飾、6 種 biome、內容全部資料化 |
| 做完還是不好玩 | 最大的風險 | **Phase 1 止損點** |
